# Data-free PBS execution-envelope E0 registration

D6 v2 is closed after its sole PBS attempt ended before the wrapper's first
persistent record. It remains execution-incomplete with no scientific verdict;
E0 neither repairs nor reruns it.

E0 is a materially separate, infrastructure-only audit. Its sole purpose is to
distinguish scheduler job start, environment propagation, exact-checkout
visibility, the approved Python/Torch runtime, first persistent write and PBS
output staging from every scientific input. The wrapper writes its attempt
marker before strict shell mode and does not source `/etc/profile`. The submitter
must create a fresh private working directory and request separate scheduler
stdout and stderr paths there.

E0 has no scientific asset path, split manifest, tensor read, metric, method,
model, training, inference, validation, outer test or GPU. It permits one
introai9 PBS attempt with CPU 1, 2 GB, GPU 0 and five minutes. Any outcome closes
E0 without repair or rerun. A pass is engineering evidence only and permits at
most the design and registration of a fresh scientific contract; it does not
reopen D6 or authorize a field read, model experiment or paper claim. The
public static site remains outside scope. Never use junjinyong.
